# 移动核心竞技场素材生产方案

> 状态：Alpha 02A 权威素材计划。凡与旧素材清单、旧比例稿或旧提示词冲突的内容，以本文和移动核心竞技场策划为准。

## 1. 目标与美术语言

正式素材采用已经确认的混合方向：

- 以 B 方案的重型机械结构、履带细节和哈迪斯式科幻坦克语言为主体；
- 吸收 A 方案的明亮黄沙、清晰墙体轮廓和街机可读性；
- UI 使用 C 方案的模块化工业框架，但避免遮挡战场和堆叠装饰；
- 俯视角像素街机表现，逻辑画布固定为 480×270；
- 玩家坦克是唯一战斗主体，移动中继核心只嵌入坦克，不出现独立中继站、基地实体或第二条基地血量。

## 2. 游戏内真实比例

24×24 像素地图格是空间标尺，不要求每张源图都裁切成 24×24：

| 对象 | 战场占地参考 | 视觉要求 |
| --- | --- | --- |
| 玩家坦克 | 约 1 格，源画布可为 32×32 | 车体方向与独立炮塔清楚，不能成为遮挡战场的大型角色 |
| 无人机/轻型敌人 | 0.5～0.7 格 | 数量多时仍易分辨弹道和碰撞范围 |
| 普通敌军 | 0.8～1.0 格 | 轮廓与攻击职责一眼可辨，整体不大于玩家 |
| 重型普通敌军 | 1.1～1.4 格 | 用宽度和装甲体现重量，不靠无边界放大 |
| 精英敌军 | 1.4～1.7 格 | 在普通轮廓上增加明确精英识别，不冒充 Boss |
| 竞技场 Boss | 2.3～2.5 格 | 允许阶段部件和大范围预警，但必须保留玩家闪避空间 |

HUD 只占画面边缘：左上显示装甲、等级和经验，右上显示波次与剩余敌人，下方以紧凑图标显示核心、辅助系统和协议。统计升级使用紧凑三选一面板；协议、维护和 Boss 奖励可以使用更完整的卡片，但不得在战斗运行时长期遮挡地图。

## 3. 小批次门禁

所有批次遵守“少量样张 → 用户确认 → 同批扩展 → 游戏内裁切与验证”的顺序，不一次生成大量未经确认的素材。

### Gate 0：真实游戏比例基线

只生成一张 480×270 逻辑比例的 16:9 游戏画面：包含完整竞技场、玩家、不同尺寸敌军、Boss 比例参考、战斗 HUD，以及统计升级和协议奖励的界面状态示意。它不是素材母版，不允许用放大的概念角色替代真实游戏视角。

通过后才能进入 Batch 1。若比例不通过，只修改这一张基线，不扩展任何素材。

### Batch 1：玩家坦克与三种核心

- 一套玩家车体和独立炮塔；
- 三种核心在光色、嵌入结构和战斗反馈上的差异；
- 四方向移动、开火、冲刺、受击、重启所需的最小帧或部件；
- 先确认一台坦克与一项核心变化，再扩展完整组。

### Batch 2：城市竞技场地形

- 黄沙、破损道路、工业地板、砖墙、钢墙、残骸、油桶和边缘阻挡；
- 四个外围入口与清晰的刷新预警区；
- 不生成底部基地防区、保护围墙或中继站占位。

Alpha 02C 已生成 `sparse-arena-sample/blockade-city-sparse-arena-v1.png` 作为单张环境样图，当前等待用户确认开放区域比例和障碍密度。确认前，它只作为 `TileMapLayer` 场景布局的视觉依据，不得直接替换运行时地形或扩展为批量素材。

### Batch 3：普通敌军与精英

- 四类城市普通敌军，对应不同接近、射击和区域压力职责；
- 一套受控精英变体规则；
- 先以四个静态轮廓和一个精英对比图确认尺寸，再制作运行部件。

### Batch 4：路障指挥车 Boss

- 2.3～2.5 格主体、炮塔、阶段部件与弱点；
- 入场、阶段转换、重击预警、击毁的最小表现；
- 大体积不能牺牲弹道和安全区可读性。

### Batch 5：HUD 与奖励界面

- 装甲、经验、等级、波次、核心、辅助系统、协议和精英/Boss 状态；
- 紧凑统计升级三选一；
- 部门协议、维护奖励和 Boss 奖励卡片；
- 不制作中继站血条、基地警报或商店页面。

### Batch 6：弹道与战斗特效

- 玩家与敌军炮弹、命中、装甲破裂、击毁；
- 冲刺、无敌、原地重启、升级、奖励确认；
- 关键协议和 Boss 攻击预警；
- 保证像素轮廓、明度层级和危险颜色一致。

### 与代码迭代的插入顺序

素材门禁不是等所有代码完成后再统一补图，而是在对应玩法迭代前提供最小视觉样张：

| 时间点 | 素材门禁 | 允许进入游戏的条件 |
|---|---|---|
| Alpha 02B 收尾 | Batch 1 先生成一台玩家坦克与一种核心变化；确认后再扩展，随后进入 Batch 2 小样 | 用户确认轮廓、机械语言、24×24 实机比例和炮塔分层 |
| Alpha 02C 前/中 | Batch 2 极稀疏城区地面、少量可破坏/钢制掩体与四周入口 | 用户确认开放区域比例和障碍密度；运行时继续使用独立 TileMap/碰撞数据 |
| Alpha 02D 前 | Batch 5 先生成 HUD、经验条和紧凑升级三选一小样 | 用户确认战斗可读性与暂停占屏 |
| Alpha 02E～02F | 扩展 Batch 1 三核心；补充协议卡框架和 Batch 6 核心/辅助反馈 | 对应规则已可在 Godot 中验收 |
| Alpha 02G 前 | Batch 3 四类敌军与一个精英比例对比样张 | 用户确认职责轮廓后再做运行部件 |
| Alpha 02H 前 | Batch 4 Boss 小样，并补齐首区 Batch 2/5/6 | 第一竞技场纵切所需素材均已确认 |

每个时间点仍严格执行“单张或极少量样张 → 用户确认 → 同批扩展”，不得因代码迭代需要而跳过视觉确认。

## 4. 文件与登记规则

- 原始生成结果存入 `asset_sources/ai_generated/<batch>/`；
- 裁切、调色和像素清理过程文件存入 `asset_sources/working/<batch>/`；
- 只有用户确认且完成游戏内可读性验证的文件，才复制到 `game1/assets/`；
- 每个生成文件都登记工具、日期、用途、完整提示词存档、原始尺寸、人工处理和采用状态；
- 文件名使用英文小写蛇形命名，并以对象职责而不是临时外观命名；
- 不下载或购买任何第三方资源，除非先重新核对来源与授权并取得用户明确确认。

## 5. 旧中继站素材处置

旧 `batch-00-style` 中含独立中继站、基地守卫布局、第二条基地血量或旧固定房间比例的图片与提示词，均已失效。它们不参与新风格继承，也不得进入新批次。

在 Gate 0 无中继站比例图通过、且 Alpha 02B 已解除运行时代码和场景依赖之后，删除旧中继站图像文件；`AI_PROTOTYPE_ASSETS.md` 继续保留来源、历史用途与删除原因的文字记录，确保审计链不断裂。

## 6. Gate 0 验收标准

- [x] 画面是正式游戏视角和 480×270 比例，不是素材表或放大概念图；
- [x] 玩家约占一格，普通敌军整体不大于玩家，精英与 Boss 层级清楚；
- [x] 竞技场为四周来敌的黄沙工业空间，不是传统底部守基地地图；
- [x] 完全没有独立中继站、基地血条、守卫围墙或第二失败目标；
- [x] HUD 信息齐全但不挤压主要战斗区域；
- [x] 统计升级和协议奖励能看出信息密度差异；
- [x] 机械细节、黄沙明度和工业 UI 符合已确认的 B+A+C 混合风格；
- [x] 一眼能判断坦克、敌人、弹道、危险区和可移动空间。

Gate 0 已由用户确认。Batch 1 玩家坦克核心状态第二版样张已于 2026-07-21 通过独立视觉门禁，并成为后续玩家坦克素材基准；扩展素材仍按“少量样张 → 用户确认 → 同批扩展”推进，未经游戏内可读性验证不得直接复制进 `game1/assets/`。
