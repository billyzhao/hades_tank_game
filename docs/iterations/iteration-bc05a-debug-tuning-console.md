# BC-05A：Debug 策划节奏调参台

## 目标与非目标

目标：在现有 Debug“竞技场验收”中增加可实时操作、可观察、可恢复、可保存的节奏调参页，并把确认结果固化到 Release 读取的正式平衡 Profile。

非目标：不新增敌军、构筑、竞技场或作弊规则；不改变奖励、Boss、重启和结算状态机；不让 Release 显示或执行写盘入口。

## 已确认参数

| 参数 | 范围 | 生效规则 |
|---|---:|---|
| 刷怪速度 | ×0.50～×2.50，步进 0.25 | 立即影响下一次刷新 |
| 场上敌军上限修正 | -3～+8，最终至少 1 | 立即影响后续补兵，不强删场上敌军 |
| 敌军移动速度 | ×0.75～×1.50，步进 0.05 | 新出生敌军 |
| 敌军攻击频率 | ×0.75～×1.75，步进 0.25 | 新出生敌军 |
| 敌军装甲 | ×0.50～×2.00，步进 0.25 | 新出生敌军 |
| 玩家移动速度 | ×0.80～×1.30，步进 0.05 | 立即生效 |
| 玩家射击频率 | ×0.75～×2.00，步进 0.25 | 立即生效 |

## 架构合同

- 正式资源：`res://resources/tuning/blockade_city_balance_profile.tres`；
- Debug 菜单只发请求，不直接修改导演、角色私有字段或源资源；
- `AppRoot` 是装配入口，负责工作副本、运行时应用、保存结果和状态回显；
- 保存入口只允许 Godot 编辑器内 Debug 运行，二次确认后由专用服务保存并重新加载校验；
- Release 始终读取正式 Profile，但不显示调参菜单；
- 初始 Profile 全部为 ×1 / +0，因此本迭代不会擅自改变已验收正式数值。

## 验收标准

1. “竞技场验收”可在“快捷验收”和“节奏调参”间切换，原按钮全部保留；
2. 每个参数可增减且不能越界，基础值、倍率、实际刷新间隔/敌军上限和未保存状态可见；
3. 标准、密集、高压、恢复已保存、恢复设计基准均产生确定结果；
4. 刷怪速度和上限在当前波生效；敌军倍率只影响后续出生单位；玩家移动和射击倍率立即生效；
5. 保存前出现确认；保存成功后 `.tres` 实际变化、重新加载一致且“未保存”消失；
6. 从编辑器外运行 Debug 时保存被拒绝并显示原因；
7. Release 不显示调参 UI，也不能触发正式资源写入；
8. 现有快捷验收、五波、Boss、重开和 Release 导出回归通过。
