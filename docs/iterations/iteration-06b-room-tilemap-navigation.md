# 迭代 06B：房间数据、TileMap 与动态导航

## 目标与非目标

目标：在已完成 06A 的奖励循环后，使第二场加载一张不同布局的工业区房间，并以可破坏 TileMap 地形驱动动态 A* 寻路。

非目标：新增协议、敌人种类、Boss、存档、音频、重做中继与重启机制不属于本合同。

## 策划验收标准

1. 第一房奖励选择后，第二场加载肉眼明显不同、非镜像的黄沙工业区布局。
2. 每个房间由 Ground、Structure、Destructible 三层 TileMapLayer 组成，钢墙与砖墙视觉/碰撞正确。
3. 敌军从不同出生边出发，绕障到中继站，既不穿墙也不原地永久卡死。
4. 打掉关键砖块后敌军在 0.25 秒内重新计算路线并利用新开通道。
5. 人为封死路线时敌军安全停下并定时重试，不报错、不污染游戏状态。

## 开发任务合同

### 必须实现

- `RoomDefinition`、`RoomWaveDefinition`、两项房间资源和由索引选择场景的运行接口。
- `NavigationGrid` 对 AStarGrid2D 的封装，重建、越界与无路回退均可测试。
- 两张房间的三层 TileMapLayer、工业 TileSet、砖块耐久与 `BrickDestroyed` 事件。
- 敌军路径提供器接口、0.25 秒路径重试、砖块破坏立即刷新路径。
- 第二战加载 `industrial_flank_room.tscn`，并完成自动化、编辑器、运行和策划可见验证。

### 必须保持不变

- 06A 协议目录、奖励算法、数值管线与生命周期语义。
- 中继总血量、坦克总装甲、一次重启的既定规则。
- 当前敌军种类和伤害/波次内容边界；本轮只更换寻路来源。

### 禁止实现方式

- 不得保留旧 `DefenseRoutePlanner` 作为运行时敌军的备用主路线；无路必须安全重试。
- 不得用逐块 `StaticBody2D` 继续承载砖墙或以脚本硬编码第二房布局。
- 不得把导航重建放入每帧 `_Process`，只能在加载、砖块状态改变或明确重置时发生。
- 不得因实现困难删减第二房、破坏更新或无路回退；需偏离时先暂停请用户确认。

### 2026-07-18：AStarGrid2D 测试宿主调整（用户已确认）

`NavigationGrid` 使用真实 Godot 原生 `AStarGrid2D`。普通 NUnit 进程在未初始化 Godot 运行时的条件下调用该对象会持续阻塞，无法提供有效的红绿测试证据。经用户确认，保留 NUnit 用于纯 C# 管线测试；将 `NavigationGrid`、后续 TileMap 与真实导航重建测试迁移至现有 `godot --headless` 正式测试宿主执行。此调整不改变玩法、数据模型、运行时架构、验收标准或测试覆盖范围。
