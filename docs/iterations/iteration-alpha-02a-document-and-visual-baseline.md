# Alpha 02A：重构文档与视觉基线

## 目标与非目标

目标：把项目入口、策划、技术、开发路线和素材生产统一到“玩家坦克是唯一战斗主体”的移动核心竞技场方案，并用一张无中继站真实游戏比例图完成正式素材生产前的 Gate 0。

非目标：本迭代不修改 Godot 场景、C# 生产代码、资源数据、自动化测试或输入；不删除当前运行时仍依赖的中继站文件；不下载、购买或批量生成素材；不宣称新竞技场玩法已经实装。

## 策划验收标准

1. 玩家坦克是唯一战斗主体，移动中继核心只存在于坦克内部；
2. 权威文档统一描述 5 座竞技场、每座 5 波后进入 Boss、战斗内即时完全暂停升级与三核心构筑；
3. 真实比例图中玩家约占一格，普通敌军不大于玩家，精英和 Boss 尺寸层级清楚；
4. 竞技场四周来敌，HUD、紧凑属性三选一和完整协议三卡的占屏比例可判断；
5. 图片和未来素材清单中不存在独立中继站、基地目标、基地血条或商店页面；
6. 用户确认 Gate 0 前不得进入 Batch 1。

## 开发任务合同

### 必须实现

- 标记六份旧文档的历史/替代关系；
- 新建移动核心竞技场技术设计；
- 更新根 README、Godot README 和素材登记；
- 新建分批素材生产计划；
- 只生成一张 Gate 0 比例图，保存完整提示词、来源、尺寸、哈希、处理和状态；
- 记录已知视觉限制，不把生成占位数字当成策划规则。

### 必须保持不变

- 当前 Alpha 01A 可执行基线；
- `game1/scripts/`、`game1/scenes/`、`game1/resources/` 与测试文件；
- 480×270 逻辑画布、24 像素地图格和已确认的玩家一格比例；
- 用户验收前不提交、不推送。

### 禁止实现方式

- 不用删除历史记录掩盖旧中继站来源；
- 不把文档目标写成当前已经实装的功能；
- 不以概念角色大图、素材表或等距视角替代真实游戏比例；
- 不生成第二张候选或扩展为批量素材；
- 不暂存 `.superpowers/`、旧 `batch-00-style/` 或未确认的 `batch-01-units/`。

### 允许/禁止修改的文件

允许：本迭代计划列出的 README、策划/技术/计划历史标记、素材计划、Gate 0 图片与登记、迭代记录。

禁止：`game1/scripts/`、`game1/scenes/`、`game1/resources/`、`game1/tests/`、解决方案与项目依赖文件。
