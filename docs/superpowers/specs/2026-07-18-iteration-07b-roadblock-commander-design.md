# 《废土中继》迭代 07B：路障指挥车完整战斗与结算设计

## 目标

在已验收的 07A Boss 骨架上，完成路障指挥车的两阶段战斗、胜利结算、重试与返回入口，形成“战斗 → 奖励 → 战斗 → Boss → 结算”的 MVP 短局闭环。

## 已确认玩法

### 第一阶段（生命值 > 50%）

- Boss 在房间内预设锚点之间缓慢换位。
- Boss 每次架设前显示 0.8 秒地面预警；仅在合法空格部署钢制路障，不能覆盖玩家、中继站、现存地形或导航关键路径。
- Boss 使用可读的三发扇形炮击。
- Boss 在威胁上限内召唤巡逻坦克；这些敌军仍使用现有 A* 路径提供器，不能退回直线穿墙或旧路线规划。
- 机枪哨作为 Boss 专属固定威胁，预警后直线短点射；不加入普通敌军池。

### 第二阶段（生命值首次 ≤ 50%）

- 停止新的路障、机枪哨和召唤循环。
- Boss 破坏指定砖墙，打开朝中继站的冲锋通道，并使导航即时刷新。
- 每次冲锋前对中继站显示 0.8 秒直线预警；冲锋期间 Boss 免疫伤害。
- 冲锋撞上 Structure 钢墙时立即被打断，进入 1.5 秒脆弱窗口；脆弱窗口结束后才能再次筹备冲锋。
- 玩家可借由被打开的通道和钢墙反弹炮弹进行反制。

### 击败与结算

- Boss 归零时，只触发一次：清除敌对实体与敌方炮弹，停止 Boss 事件源，显示结果页。
- 结果页显示种子、已选协议、中继站完整度和本局耗时。
- “重试”创建新 `RunState` 并从首房开始；“返回”清理本局并回到应用外壳。

## 架构

```text
BossDefinition + BossRoom
       ↓
BossEncounterController
 ├─ BarrierDeployment（合法格校验、TileMap 写入、导航刷新）
 ├─ BossGunEmplacement（专属固定威胁）
 ├─ BossSummonController（巡逻坦克、威胁上限、A* provider）
 └─ RoadblockCommander（锚点移动、扇形炮击、冲锋、脆弱窗口）
       ↓
RoadblockCommander.Defeated
       ↓
RunResultScreen（显示与重试/返回请求）
```

- 将现有 `AppRoot.CreatePathProvider` 提取为可复用的房间导航工厂；普通敌军与 Boss 召唤物均从同一工厂获得 A* provider。
- `BarrierDeployment` 只修改 Boss 房 `Structure` TileMapLayer 的运行时单元，不修改 TileSet/Resource；部署和拆除都向导航工厂请求重建。
- `RoadblockCommander` 保持 07A 的阶段判定权；07B 只订阅阶段事件，不修改 `BossPhaseController` 的 50%/不可逆语义。
- 结果页只读取 `RunState` 和计时快照；重试/返回请求由 `AppRoot` 唯一处理，避免 UI 直接改变运行状态。

## 非目标

- 不新增普通敌军类型、协议、房间、素材来源、音频包或局外成长。
- 不改变玩家装甲、中继站耐久、战场重启和协议数值。
- 不创建通用行为树、对象池或多区域 Boss 框架。

## 验收标准

1. 第一阶段的路障、炮击、召唤和机枪哨均有可读预警，且路障不封死玩家/中继站导航。
2. 第二阶段只触发一次；指定砖墙消失、通道可走、敌军在 0.25 秒内重寻路。
3. 冲锋预警可躲避；撞钢墙后 Boss 停止并在 1.5 秒脆弱窗口内可受伤。
4. Boss 击败后敌对实体与敌方炮弹清理，结果页数据正确，重试与返回无残留信号。
5. 06A/06B/07A 回归不退化。
