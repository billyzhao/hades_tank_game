# 《废土中继》混合表现迭代设计

## 1. 目标

将已验证的灰盒战斗原型提升为高质量像素街机原型：玩家在不阅读说明的情况下，也能识别坦克移动、开火、命中、敌军职责与中继站压力。该迭代不调整伤害、波次、重启或房间结算规则。

## 2. 已确认的视觉方向

- 俯视角像素街机表现，逻辑画布保持 480×270，窗口保持 1440×810。
- 主角为重型、机械细节丰富的科幻坦克：宽履带、厚装甲、独立炮塔与外露能量部件。
- 场景为黄沙废土工业区：沙地、损毁的工业围挡、钢墙、砖墙、残骸与绿色中继站。
- 采用混合方式：核心角色/装置像素资源、程序化或简单精灵特效、少量可替换基础音效共同组成可玩表现。

## 3. 视觉规格

| 对象 | 原型规格 | 可读性规则 |
| --- | --- | --- |
| 玩家坦克 | 32×32 像素车体；独立炮塔；2 帧履带运动 | 沙黄/深灰装甲；冲刺时出现沙尘；炮口和炮塔后坐清楚 |
| 巡逻坦克 | 24×24 像素，窄炮塔 | 黄色，追击玩家 |
| 突击车 | 24×24 像素，短车身 | 橙色，移动节奏更快 |
| 攻城炮车 | 24×24 像素，长炮管 | 紫色，优先攻击中继站 |
| 中继站 | 32×40 像素，绿能核心 | 受击时白闪与绿色能量波；耐久降低仍由 HUD 显示 |
| 战场 | 480×270 模块化沙漠工业地面 | 砖墙可破坏、钢墙可反弹的语义必须保留 |

## 4. 动态反馈

- 移动：履带两帧切换、轻微车体摇晃；冲刺产生短沙尘尾迹。
- 开火：炮口火光持续不超过 0.08 秒；炮塔向后偏移 2 像素并在 0.10 秒内回正。
- 炮弹：金色玩家拖尾、红色敌方拖尾；钢墙命中产生火花，砖墙销毁产生碎片。
- 伤害：坦克、敌军与中继站各自短暂白闪；敌军销毁产生小型爆炸。
- 镜头：玩家开炮为极轻震动，命中与爆炸为中等震动；震动仅改变渲染偏移，不改变物理坐标或瞄准。
- 音频：最小集合包含开炮、钢墙命中、砖墙破裂、敌军爆炸、冲刺、中继站受击。音频必须可关闭，默认音量适中。

## 5. 架构边界

- `WeaponController`、`Projectile`、`HealthComponent`、`DestructibleTerrain` 和 `EnemyTank` 继续拥有规则结算；它们仅新增事实信号，例如 Fired、Impacted、Destroyed。
- `VisualFeedbackController`、`CameraShakeController`、`AudioFeedbackController` 订阅事实信号并生成纯表现。它们不得调用 `ApplyDamage`、改写 `RunState` 或改变碰撞层。
- 特效的寿命、颜色和震动数值集中在一个可编辑配置资源中；资源缺失时必须安全降级为无特效，而不是阻断战斗。
- 所有运行时表现节点在场景卸载时自动清理，不遗留粒子、音频或信号连接。

## 6. 资源策略与授权

- 本轮不购买、不下载付费素材。
- 主角坦克和中继站允许使用 AI 辅助的原型图，但入库前必须像素整理并登记来源/用途。
- 通用沙地、碎片、墙体和音效优先使用授权明确的可复用资源；未获得资源时使用项目内制作的像素占位，不复制未授权素材。
- 所有来源登记到 `asset_sources/THIRD_PARTY_ASSETS.md`，并将可替换资源放在 `game1/assets/` 对应目录。

## 7. 交付与验收

交付分为视觉基线、战斗动态、声音与整体打磨三个独立验收点。每个验收包必须提供“操作 → 预期画面/状态变化”脚本；在 Godot 中可见地验证后，再由用户确认提交。

最终验收：连续完成一场三波守点战，玩家能通过画面分辨所有对象职责；移动、开火、命中、破坏、重启和中继站受击均有即时反馈；自动化测试、Debug/Release 构建与无界面启动均通过。
