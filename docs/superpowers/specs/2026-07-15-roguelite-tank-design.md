# 废土中继：肉鸽坦克战 — 游戏策划

## 1. 项目定位

一款 Godot 4 俯视角动作肉鸽游戏。它继承 FC 坦克大战的可破坏地形、弹道对射和基地守卫压力，结合现代动作肉鸽的房间路线、三选一构筑、局外横向解锁和 20–30 分钟单局节奏。

- **玩家幻想**：驾驶一辆不断改装的抵抗军先锋坦克，在敌军包围中守住前线中继站。
- **操作**：WASD/左摇杆移动；鼠标/右摇杆独立瞄准炮塔；主炮射击，冲刺与主动技能用于脱险或爆发。
- **美术**：高细节像素街机风为主，结合微缩战场的立体层次；保证坦克轮廓、弹道、砖墙/钢墙和掉落物的可读性。
- **世界观**：战后废土抵抗军由移动要塞出击，对抗占领城区与资源区的军阀装甲部队。

## 2. 单局循环与失败条件

单局时长目标为 20–30 分钟，共 4 个区域，每区约 6–8 个房间并以 Boss 收尾。首版只验证第一个区域的短循环。

```text
移动要塞整备 → 选择下一房间 → 战斗并保护中继站
→ 选择战利品 / 维修 / 商店 → 下一房间 → 区域 Boss → 结算
```

### 双生命线

| 资源 | 规则 |
|---|---|
| 中继站耐久 | 全局初始 100；敌军攻击中继站时扣除，归零即本局失败。 |
| 坦克装甲 | 全局资源，不会在每个房间自动回满；归零时触发战场重启。 |
| 战场重启 | 每局有限次数。坦克报废时消耗一次并在当前房间继续；重启耗尽后再次报废则本局失败。 |

中继站相关奖励包括修复组件、装甲板、自动机炮、应急护盾和牵引协议（把致命伤部分转移给中继站）。这让守点压力持续存在但不因一次失误立即毁掉长局构筑。

## 3. 房间与地图

采用**手工设计的战斗房间 + 随机敌群、奖励与房间顺序**。首版做 12–16 个城区房间，优先保证掩体、反弹路线、敌军出生点和中继站位置经过设计。

战斗房间中，敌军自数条路线压向中继站。玩家可拦截、利用砖墙反弹弹道、破坏掩体开路，或依靠构筑部署炮塔和陷阱。房间完成通常获得三选一军械协议；特殊房提供维修、加固中继站、商店或高风险挑战。

## 4. 构筑体系

采用**核心模块 + 四个部门协议**的混合结构。

### 核心模块

核心模块定义坦克的基础战术身份，例如高速侦察底盘、重装堡垒底盘、布雷工兵底盘。稀有原型机可改变规则，例如“炮弹必定反弹一次”“冲刺留下燃烧履带”“中继站机炮复制特殊弹”。

### 军械协议

每个房间结算提供可理解的三选一。协议来源于抵抗军部门，而非超自然赐福；同部门协议提高彼此出现和联动概率，但允许跨部门混搭。

| 部门 | 身份 | 代表协议 |
|---|---|---|
| 前线兵工局 | 火炮与弹药 | 穿甲、分裂、反弹、蓄力重炮。 |
| 工程兵团 | 地形与守点 | 自动炮塔、补墙、地雷、拦截网。 |
| 侦察电子组 | 机动与控制 | 额外冲刺、诱饵信号、减速电场、锁定追踪弹。 |
| 后勤维修署 | 生存与资源 | 战后维修、护盾、额外重启、基地装甲板。 |

首版目标为 8–12 个协议，并至少有两组明显联动。例如反弹弹 + 钢墙把窄巷变为弹射走廊；冲刺带电 + 诱饵信号鼓励冲入敌群再撤离；自动炮塔 + 中继站防线可短暂解放玩家去处理高威胁单位。

## 5. 敌人与 Boss

敌人坚持单一、可读的战术职责。炮口朝向、充能动画和地面警告明确表达攻击意图；精英仅添加一条规则，不靠血量膨胀制造难度。

| 职责 | 单位 | 行为与反制 |
|---|---|---|
| 基础火力 | 巡逻坦克 | 慢速转炮、直线点射；学习对射和借墙反弹。 |
| 追击 | 突击车 | 快速贴近、短距离连射；可绕墙、布雷和冲刺脱离。 |
| 远程压制 | 迫击炮车 | 锁定地面后延迟落弹；离开红圈或切断视线。 |
| 攻城 | 攻城炮车 | 优先攻击中继站，高伤害且移动慢；必须优先处理。 |
| 地形干扰 | 工程车 | 修复掩体、布雷或架设路障；可被抢先打断。 |
| 自爆突入 | 自爆工程车 | 冲向中继站或玩家；击毁时产生小范围爆炸。 |
| 指挥支援 | 指挥坦克 | 给附近敌军护盾或加速，迫使玩家切后排。 |

精英词缀包括装甲化、过载射速、护盾连线和复仇协议（死亡后留下危险区域）。

### Boss

| 区域 | Boss | 阶段设计 |
|---|---|---|
| 封锁城区 | 路障指挥车 | 第一阶段布置钢墙、机枪哨并召唤巡逻坦克；第二阶段撞毁砖墙制造通向中继站的冲锋通道，玩家可用新通道反弹攻击它。 |
| 废弃工厂 | 熔炉装甲列车 | 沿轨道投放敌军和燃烧油桶；轨道损毁后停为重炮平台，击毁两个散热车厢才可伤害核心。 |
| 干涸水库 | 两栖重炮平台 | 在水道换位并齐射；后期开闸淹没低地，召唤两栖小队进攻中继站。 |
| 军阀要塞 | 军阀旗舰坦克 | 多炮塔与能量护盾压制；护盾破裂后高速追击并发射反弹重弹，击破侧面反应堆终结。 |

最小原型只实现巡逻坦克、突击车、攻城炮车及路障指挥车，以验证守点与地形玩法。

## 6. 区域与局外成长

| 区域 | 地形特色 | 追加威胁 |
|---|---|---|
| 封锁城区 | 砖墙、窄巷、钢墙 | 轻型突击车、迫击炮车。 |
| 废弃工厂 | 传送带、油桶、机械门 | 自爆工程车、布雷车。 |
| 干涸水库 | 浅水、堤坝、开阔火线 | 两栖坦克、远程狙击炮。 |
| 军阀要塞 | 激光栅栏、炮台、防爆墙 | 精英混编部队。 |

局外成长只做横向解锁：新底盘、主动技能、协议池、房间事件及开局战术指令。失败或通关带回“废墟样本”解锁内容与叙事，不做无限伤害或生命值成长。

## 7. Godot 技术方案

详细实现约束见：[《废土中继：Godot 技术设计》](./2026-07-15-roguelite-tank-technical-design.md)。本节只保留策划层面的技术概要。

延续现有 **Godot 4.7 .NET / C# 2D** 项目。最终以低分辨率像素画布配合整数缩放渲染；战斗逻辑使用连续世界坐标，保证移动和独立瞄准手感。

### 运行时模块边界

| 模块 | 职责 |
|---|---|
| `RunController` | 单局路线、重启次数、房间切换、结算。 |
| `RoomController` | 当前房间生命周期、胜负判定和奖励入口。 |
| `PlayerTank` | 移动、炮塔瞄准、装甲、冲刺和主动技能。 |
| `Weapon` / `Projectile` | 发射、命中、反弹、穿透、爆炸。 |
| `EnemyTank` | 敌人状态与单一行为策略。 |
| `EnemyDirector` | 根据波次和威胁预算生成敌军。 |
| `RelayStation` | 耐久、护盾、修理和防线接口。 |
| `DestructibleTerrain` | 砖墙破坏、钢墙阻挡、地形查询。 |
| `BuildController` | 核心模块、协议堆叠与事件触发。 |

### 数据资产

用 Godot `Resource` 配置内容，避免将平衡数值写死在代码中：

- `EnemyDefinition`：属性、武器、AI 类型、威胁值；
- `WeaponDefinition`：射速、伤害、弹道、反弹/穿透规则；
- `ProtocolDefinition`：部门、稀有度、触发条件、效果参数、前置标签；
- `RoomDefinition`：房间场景、出生波次、中继站位置、奖励类型；
- `ModuleDefinition`：底盘与原型机的基础改装。

## 8. 最小可玩原型（MVP）

1. 一个封锁城区房间；
2. 玩家移动、独立瞄准、主炮、冲刺；
3. 可破坏砖墙与不可破坏钢墙；
4. 中继站耐久、坦克装甲和一次战场重启；
5. 巡逻坦克、突击车、攻城炮车；
6. 8–12 个协议和至少两组联动；
7. 路障指挥车 Boss；
8. 至少一次“战斗 → 三选一协议 → 下一战斗”的短循环。

验收标准：玩家会主动利用墙体与弹道、优先处理攻城单位；协议选择显著改变下一场的操作；失败后愿意立即再开一局。

## 9. 范围与非目标

MVP 不包含后续三个区域、其余 Boss、完整局外叙事、全部模块池、复杂程序生成地图或在线多人。它们在核心循环验证后按区域和内容包逐步加入。
