# BC-04 音频、手感与玩家体验实施计划

**目标：** 在不改变 BC-01～BC-03 玩法、数值和架构的前提下，让封锁城区的重要动作、危险和阶段变化通过声音、适量震动、短促停顿和正式提示直接可辨识。

## 范围

- 建立 `Master / Music / Ambience / SFX / UI` 音频总线与设置映射；
- 接入玩家履带、主炮、冲刺、受击、低装甲、重启与重启完成音效；
- 接入四类敌军开火、刷新预警、精英过载和击毁音效；
- 接入 Boss 入场、路障、哨位、冲锋预警、冲锋、弱点、阶段转换和击毁音效；
- 接入 UI 移动、确认、升级、维护、失败和完成音效；
- 接入黄沙工业环境循环、五波同步分层音乐和 Boss 音乐过渡；
- 按小/中/大事件分级补强相机震动、命中停顿、受击闪光和低装甲危险提示；
- 检查 HUD 遮挡、暂停原因叠加、焦点恢复和现有键位冲突；
- 新增 BC-04 资源、逻辑与场景级自动化测试，并同步素材主清单。

## 非范围

- 不新增第二至第五竞技场、敌军、Boss、协议、辅助或数值成长；
- 不改变五波时长、刷新预算、奖励概率和 Boss 战斗规则；
- 不加入第三方音频插件或外部版权素材；
- 不制作设置菜单、完整无障碍菜单或局外选项系统；
- 不执行 BC-05 的完整压力、Release 导出和最终平衡。

## 音频生产与接入

1. Batch 09 使用项目自有确定性合成脚本生成 WAV，保留脚本、参数、清单和来源说明；
2. 短音效使用单声道 WAV；环境和音乐使用对齐的小节循环，并由运行时设置循环点；
3. 同类高频声音提供多变体或轻微音高变化，避免连续开火机械重复；
4. 音频进入运行目录后先登记为 `CANDIDATE`；用户实机听感验收通过后才能改为 `CONFIRMED`；
5. 战斗逻辑只上报事实；音频、震动和停顿由表现控制器订阅，不参与伤害、状态机或随机结果。

## 实现顺序

1. Batch 09 音频源、总线、资源目录与设置映射；
2. 玩家、敌军、精英、Boss 和 UI 事件接线；
3. 自适应战斗音乐、Boss 过渡、低装甲和分级手感；
4. 素材登记、集中构建、Headless、主场景启动和实际 Godot 验收。

## 完成门禁

- 不看日志也能从声音区分玩家开火、敌军开火、受击、低装甲、重启和失败；
- 迫击、刷新、精英、路障、哨位、冲锋、弱点、Boss 阶段和击毁具有各自提示；
- 五波音乐强度随波次提升，Boss 入场切换到独立段落，环境声持续但不压过危险音效；
- UI 焦点移动、确认、升级、维护、失败和完成有反馈，鼠标与键盘焦点均可用；
- 震动只修改 `Camera2D.Offset`，短停顿只用于重要命中且自动恢复，不影响瞄准和状态机；
- 低装甲状态不依赖日志，HUD 与危险提示不遮挡主要战斗区域；
- 音频设置使用线性值转 dB，缺失旧存档字段时安全采用默认值；
- 集中构建、纯 C# 测试、相关 Headless 套件和 Godot 主场景启动全部通过；
- 用户验收前不提交或推送。
