# BC-05：平衡、稳定与发布候选版执行计划

## 1. 目标

把已经通过 BC-01～BC-04 验收的封锁城区纵切收敛为 `0.1.0-rc1` Windows 独立试玩构建。玩家必须能够脱离 Godot 编辑器完成“标题 → 核心选择 → 五波战斗与波间构筑 → 路障指挥车 → 结算 → 重试/返回标题”的完整闭环。

## 2. 范围

必须完成：

1. 三核心、多固定种子和不同路线的完整状态机与奖励审计；
2. 维修 30% 边界、即时升级队列、精英、Boss、失败与重开回归；
3. 敌军出生安全、刷新结束、待出生单位、清场和异步退出回归；
4. 现有敌军、炮弹和持续效果数量的结构完整性回归，不设置性能跑分门禁；
5. Debug 策划验收入口与 Release 正式界面的边界检查；
6. Godot 4.7 .NET Windows 导出预设、版本信息、启动说明与已知限制；
7. 最终运行素材审计与 BC-05 迭代证据。

本迭代不实现：

- 第二至第五竞技场、商店、装备栏或新敌军；
- 新构筑路线、新表现系统或未由测量证明必要的对象池/ECS；
- 对已经通过验收的正式 UI、美术和音频进行主观重做；
- 通过硬编码、删减波次或降低压力目标换取导出通过。
- 性能跑分、Profiler 调优、对象池或更新频率改造；用户于 2026-07-27 明确要求本轮专注功能测试和验收。

## 3. 架构约束

- `RunState` 继续保存单局事实；
- `ArenaController` 继续负责五波、奖励和 Boss 状态；
- `WaveDirector` 继续负责刷新、入口和存活敌军；
- `BuildController`、`RewardController` 和 `LevelUpController` 继续拥有构筑写入口；
- `AppRoot` 只组合和转发，不新增奖励、Boss 或性能专用私有规则；
- 导出预设由 Godot 编辑器生成后纳入版本控制，构建产物留在被忽略的 `build/`。

## 4. 实现顺序

1. 建立 BC-05 迭代合同、版本和 Windows 预设；
2. 新增完整流程/平衡审计宿主，覆盖三核心、多种子、五波、奖励、Boss 与重开；
3. 检查 Debug/Release 边界和最终素材清单；
4. 安装与 Godot 4.7.stable.mono 精确匹配的导出模板，生成 Windows Release；
5. 对独立 EXE 执行启动、输入、完整流程和重复开局冒烟；
6. 集中执行完整构建、纯 C#、全部相关 headless、集成、资源扫描和可见运行复验。

## 5. 完成门禁

- Debug 与 Release 构建均为 0 错误；
- 纯 C# 测试全部通过；
- BC-05 流程审计覆盖 3 核心 × 多种子，固定输入结果稳定且无死候选；
- 维修保障只在装甲严格低于 30% 时必含修复，恰好 30% 时不强制；
- 现有结构数量回归无崩溃、卡死或节点失控；本轮不以性能指标作为交付门禁；
- 主场景、五波、Boss、结算、失败和重开相关宿主全部通过；
- Release 构建不显示 Debug 验收入口；
- Windows 构建可在不启动 Godot 编辑器时运行；
- 最终素材清单中，封锁城区实际交付引用不存在未解释的 `MISSING`、`PROVISIONAL` 或 `PARTIAL`；
- 用户验收通过前不提交、不推送 BC-05。
